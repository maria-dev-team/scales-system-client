# DukenAI Scales

Electron-приложение на React и TypeScript для синхронизации весовых товаров
из Maria и загрузки в весы Rongta RLS1100. Основа проекта — `pos-system-client`:
electron-vite, main/preload/renderer и локальный каталог SQLite в отдельном worker.

## Recommended IDE Setup

- [VSCode](https://code.visualstudio.com/) + [ESLint](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint) + [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode)

## Project Setup

Используйте Node.js 22 и npm. Версия Node.js указана в `.nvmrc`.

### Install

```bash
nvm use
npm ci
cp .env.example .env
```

Если `nvm` не установлен, установите Node.js 22 самостоятельно. На Windows
PowerShell скопируйте конфигурацию командой `Copy-Item .env.example .env`.

### Development

В `.env` укажите `VITE_API_URL` — корневой адрес API без `/v1`, например
`http://localhost:4004`. Это публичная настройка сборки; секреты здесь не хранятся.
После изменения адреса перезапустите dev-сервер или пересоберите приложение.

```bash
npm run dev
```

Dev-сервер использует `http://localhost:5175`. Добавьте этот origin в
`CORS_ORIGINS` локального бэкенда, сохранив адреса POS и web-клиента, и перезапустите
бэкенд. Если порт занят, приложение завершит запуск с ошибкой.

Собранное приложение использует origin `maria://app`, как POS. Сервер должен
разрешать его в CORS с credentials. Для production нужен HTTPS API
и refresh-cookie с `SameSite=None; Secure`.

### Build

```bash
npm run build:win
```

Сборка создаёт Windows x64 NSIS-установщик `dist/dukenai-scales-setup.exe`.
На компьютере пользователя отдельный Node.js не требуется. Для проверки
приложения на macOS доступны `npm run dev` либо `npm run build` и `npm start`;
отдельная упаковка для macOS пока не настроена.

## Windows releases

Workflow `Release Windows` собирает и загружает установщик при публикации
GitHub Release. Версия приложения берётся из тега вида `vMAJOR.MINOR.PATCH`.

В **Settings → Secrets and variables → Actions → Variables** задайте:

- `SCALES_API_URL` — адрес production API, например `https://api.dukenai.kz`, без `/v1`.

Откройте **Releases → Draft a new release**, создайте новый тег, например
`v0.1.3`, выберите `main` и опубликуйте релиз. Workflow выполнит проверки и
`npm run release:win`. Менять и коммитить `package.json` перед релизом не нужно.
Постоянный адрес последнего установщика:

```text
https://github.com/maria-dev-team/scales-system-client/releases/latest/download/dukenai-scales-setup.exe
```

Для приватного репозитория скачивание требует авторизации GitHub. Подпись
установщика и автообновление внутри приложения пока не настроены.

## Вход и выбор магазина

Для первого входа нужны интернет, доступный API и учётная запись Maria.
После входа выберите организацию и магазин. На главном экране доступны
«Каталог товаров», «Настройка весов» и кнопки смены организации и магазина.
После смены организации магазин нужно выбрать явно.

Приложение использует авторизацию с `client_type: "web"`; кассовая смена
не требуется. Пароль не сохраняется. Настройки подключения и локальные данные
сохраняются между запусками; данные другого магазина не используются.

## Синхронизация каталога и работа без интернета

При входе с выбранным магазином, восстановлении сессии или завершении выбора
магазина каталог автоматически загружается в локальную SQLite уже на главном
экране. Синхронизируются весовые товары с единицей `kg`, цены магазина и профиль
весовых штрихкодов. Прерванная загрузка не подменяет последнюю полную копию.

Дальнейшие изменения проверяются раз в минуту. Кнопка «Обновить каталог»
запускает обновление вручную и показывает его результат после завершения.
«Остановить синхронизацию» приостанавливает автоматические обновления до ручного
запуска или нового подключения сессии. Смена магазина отменяет синхронизацию
предыдущего контекста. Загрузка каталога сама по себе не отправляет товары на весы.

Один запуск проходит все страницы и ожидает завершения операций сервера сам:
повторно нажимать «Обновить каталог» между порциями не требуется. Остановку,
ошибки связи и ограничения сервера приложение обрабатывает отдельно от успешного
завершения; уже сохранённые курсоры позволяют продолжить загрузку.

Профиль организации сохраняется из metadata, включая пустые ответы без товаров.
Старая `revision` не откатывает настройки. Диапазоны `issued_plu_ranges`
объединяются, даже при одинаковой ревизии; они включают недоступные товары
организации и не определяют список для выгрузки. Схема SQLite 4 добавляет
отдельное хранилище профилей, сохраняя каталог, курсоры и историю передачи.

После успешной онлайн-проверки доступа приложение сохраняет разрешение на
восемь часов. В этот период без интернета можно открыть сохранённый каталог
и отправить товары на весы, в том числе после перезапуска. Возраст цен показан
отдельно. Для перезапуска офлайн нужен доступный Electron safeStorage;
выход, истечение срока или подтверждённый отзыв доступа закрывают локальный доступ.

База и история операций находятся в `userData/catalog/`. Кэш разделён по API,
пользователю, членству, организации и магазину. Пароли и токены в SQLite не хранятся.

## Подключение к весам и весовые штрихкоды

Подключите весы по Ethernet. Узнайте IP и маску в меню весов и назначьте
компьютеру свободный адрес той же подсети. Для прямого подключения шлюз и DNS
не требуются. Приложение не меняет сетевые настройки ОС: если для работы
с весами вы отключали DHCP, после работы верните прежние параметры.

В «Настройке весов» укажите IP, UDP-порт и Ethernet-адаптер, выберите кодировку
названий ASCII или Windows-1251 и сохраните подключение. Подтверждение настроек
означает проверку оператором пробной этикетки, а не проверку доступности по сети.

В web-клиенте Maria откройте **Настройки → Организация → Весовые штрихкоды**,
назначьте префикс и включите профиль. Приложение использует сохранённый в API
префикс; `20` — предложение web-формы, а не обязательная настройка весов.
Префикс `29` для этого профиля не поддерживается.

Поддерживается EAN-13 формата `ean13-weight-v1`: префикс организации (2 цифры),
PLU (5), вес в граммах (5) и контрольная цифра. Перед массовой загрузкой
проверьте на одной этикетке тип штрихкода **07**, отдел = префикс организации,
единицу kg, цену с двумя знаками после запятой и выбранную кодировку названия.
Обычные штрихкоды с таким же префиксом допустимы; неоднозначность при сканировании
разрешается в POS. Неподтверждённые настройки блокируют загрузку.

При изменении префикса или ревизии текущая выгрузка останавливается. Приложение
показывает «Требуется настройка» и ручные шаги по руководству RLS1100. Проверьте
новую этикетку, замените старые этикетки и подтвердите настройки заново.
После смены префикса Maria распознаёт вес только по новому префиксу.
Затем подготовьте весь каталог для повторной выгрузки. Подтверждение старой
ревизии не принимается. При выключенном профиле или отсутствии префикса
новая выгрузка запрещена.

## Загрузка товаров на весы

В каталоге нажмите «Подготовить весь каталог» или выберите товары и нажмите
«Подготовить выбранные». Предпросмотр показывает готовые товары, причины
исключения остальных и ранее загруженные PLU, которые нужно удалить с прибора.

Для отправки нужны активный товар в килограммах, уникальный `scale_plu`,
цена магазина и название `scale_name` либо `name` до 36 байт в выбранной кодировке.
Неподдерживаемые символы не заменяются, названия не обрезаются автоматически.
Исправьте данные в Maria и обновите каталог. За один запуск можно отправить
до 10 000 товаров.

Если готовых товаров больше 10 000, передавайте их выбранными группами.
Требование полной повторной выгрузки сохраняется между запусками и снимается,
когда подтверждения текущей ревизии покрывают все готовые карточки с актуальными
данными; неизвестный результат передачи не считается подтверждением.

Подтвердите загрузку в предпросмотре. Товары отправляются последовательно
с ожиданием ответа; прогресс и остановка доступны в интерфейсе. Изменившиеся
после предпросмотра данные требуют повторной подготовки. Во время передачи
смена организации, магазина и редактирование подключения заблокированы.

После таймаута автоматического повтора нет: товар мог быть записан. Проверьте
его на весах перед повтором. Подтверждение пакета не заменяет проверку товара
и печати на приборе. Историю и байты обмена можно сохранить в JSON/TXT.

Удалённые товары исключаются из локального каталога после синхронизации;
неактивные и карточки без цены не отправляются. Если ранее загруженная карточка
удалена, вышла из kg или недоступна, новая выгрузка блокируется до отдельно
подтверждённой очистки всех товаров. Из предупреждения можно открыть настройки,
очистить весы и затем загрузить весь актуальный каталог. Подтверждённой команды
удаления одного PLU нет; нулевая цена не используется для имитации удаления.
Изменение оставшихся товаров в завершённой копии каталога также останавливает
текущую передачу и требует нового предпросмотра. Пустое обновление её не прерывает.
Удалённая печать пока не реализована.
Макет этикетки загружается отдельно через официальный RLS/RTLabel.

## Удаление всех товаров с весов

В «Настройке весов» нажмите «Удалить все товары с весов» и подтвердите адрес
устройства. Очистка удаляет все PLU, включая загруженные другими программами
и магазинами. Каталог Maria, локальная БД и макеты этикеток остаются.
Операция доступна только для проверенного профиля `LB1.00 / LS` с именами 36 байт.

Загрузка и очистка одновременно не выполняются. Остановка не отменяет уже
отправленные команды; после потери ответа результат отмечается как неизвестный.
Проверьте товары на весах перед повтором. Прерванная операция после перезапуска
не продолжается автоматически. Отчёт об очистке можно сохранить в JSON/TXT.

Команды проверены по официальному RLS1000 v1.129 и в UDP-тестах; аппаратная
проверка очистки на RLS1100 ещё требуется. После первого запуска убедитесь,
что прежние PLU не вызываются, затем загрузите актуальный каталог.

## Аппаратная проверка MARIA-255

Программные проверки используют SQLite, backend fixtures и локальный UDP-эмулятор.
Работа с реальными весами в рамках разработки не выполнялась.

1. На тестовом устройстве проверьте тип 07, kg, два знака цены и префикс `05`;
   после изменения профиля на `27` подтвердите настройки заново. Ручные шаги
   доступны в разделе настройки весов; глобальные параметры не применяются
   приложением автоматически.
2. Для PLU `4245` и стабильного веса `0.185` кг ожидается `2704245001850`.
   Сравните фактический штрихкод, цену за кг и сумму. Пример в приложении
   показывает ожидаемый формат, а не результат чтения с прибора.
3. Во время длинной загрузки измените профиль в Maria: следующие товарные пакеты
   должны остановиться, а интерфейс потребовать настройки и новой полной выгрузки.
4. Удалите тестовую карточку из магазина, обновите каталог и выполните отдельно
   подтверждённую очистку. Убедитесь на весах, что старый PLU не вызывается;
   после полной выгрузки проверьте оставшиеся товары и сохранённый макет этикетки.

Префикс `20` в [backend fixtures](./test/fixtures/ean13-weight-v1.json)
синтетический и не задаёт настройки реального оборудования.

## Проверки и CI

```bash
npm test
npm run lint
npm run typecheck
npm run format:check
npm run build
npm run smoke:catalog
```

`smoke:catalog` проверяет собранный worker, SQLite и офлайн-доступ во встроенном
Node.js Electron с отдельной временной базой. Workflow `Build` выполняет проверки
и сборку Windows для PR в `main` или при ручном запуске. Установщик хранится
в артефакте `scales-windows-<commit>` 14 дней; в этой проверочной сборке API
направлен на `http://localhost:4004`. Для production используйте GitHub Releases.
Отдельный workflow `Lint` проверяет ESLint и форматирование на Ubuntu.

Подробнее об устройстве проекта — в [ARCHITECTURE.md](./ARCHITECTURE.md).
