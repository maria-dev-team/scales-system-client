# DukenAI Scales

Electron-приложение для подготовки и загрузки товаров в весы Rongta RLS1100.
Каркас и страница входа перенесены из `pos-system-client`.

Основной экран приложения — Maria: вход, выбор организации и магазина,
локальный каталог весовых товаров и ручная выгрузка товаров в весы.
Каталог сохраняется в SQLite в отдельном worker, как в POS.

## Первый запуск на Windows

1. Откройте GitHub Actions → Build для нужного коммита. Скачайте артефакт
   `scales-windows-<commit>`, распакуйте ZIP и установите `dukenai-scales-setup.exe`.
   Установщик можно перенести с Mac на ПК флешкой; отдельный Node.js не нужен.
2. Запустите приложение, войдите в Maria и выберите организацию и магазин.
   Откройте «Каталог товаров» и дождитесь загрузки данных из Maria.
3. Сохраните текущие настройки Ethernet ПК и подключите весы кабелем.
   Посмотрите фактический IP и маску в меню весов. Назначьте ПК другой адрес
   той же подсети; для прямого подключения шлюз и DNS не требуются.
4. На главном экране откройте «Настройка весов». Введите IP весов, UDP-порт
   и выберите проводной адаптер. Проверьте параметры пробной этикетки и сохраните
   подключение. Приложение само не меняет сетевые настройки Windows.
5. Вернитесь в каталог, подготовьте загрузку выбранных товаров и подтвердите
   отправку. Проверьте товар и печать на весах; отчёт о передаче можно сохранить
   из приложения.
6. После работы верните прежние настройки Ethernet, включая DHCP, если он был включён.

## Запуск

Используйте Node.js 22 и npm:

```sh
nvm use
npm ci
cp .env.example .env
npm run dev
```

В `.env` задайте `VITE_API_URL` — корневой URL API без `/v1`, например
`http://localhost:4004`. Это публичная настройка сборки, не место для секретов.
После изменения адреса перезапустите dev-сервер или пересоберите приложение.
Для авторизации в разделе Maria нужен доступный бэкенд и существующая учётная
запись.

Dev-сервер весов использует `http://localhost:5175`. Добавьте этот адрес в
`CORS_ORIGINS` локального бэкенда, сохранив разрешённые адреса POS и web-клиента,
и перезапустите бэкенд. Если порт 5175 занят, запуск завершится с ошибкой:
приложение не перейдёт незаметно на другой порт, отсутствующий в CORS.

Если Electron установлен неполностью, проверьте `node --version`, переключитесь
на Node.js 22 через `nvm use` и повторите `npm ci`.

## Авторизация

Приложение использует существующие `/v1/auth/login`, `/v1/auth/refresh`,
`/v1/auth/logout` и `/v1/users/me`. В login передаётся `client_type: "web"`,
чтобы не зависеть от кассовых смен. Пароль не сохраняется. Access token хранится
в `sessionStorage` под ключом `scales.access-token`, refresh token — в HttpOnly
cookie, которой управляет сервер. Logout очищает состояние после успешного
ответа сервера; ошибка сети оставляет возможность повторить выход.

После входа выберите организацию и магазин. Списки загружаются из
`/v1/organizations` и `/v1/auth/context`, выбор сохраняется через
`/v1/auth/select-context`. Показаны только активные членства и магазины из
доступной пользователю области. После выбора организации магазин нужно указать
явно, даже если сервер автоматически назначил основной. Для уже выбранного и
доступного магазина открывается «Рабочее место» с карточками «Каталог товаров»
и «Настройка весов». Организация и магазин показаны отдельными блоками с кнопками
смены только на главном экране. Таблица товаров загружается при открытии каталога. Ошибки загрузки можно повторить; если доступных
магазинов нет, можно вернуться к выбору организации.

После входа с полным контекстом или завершения выбора магазина каталог
автоматически синхронизируется с локальной БД, уже на домашнем экране.
Это работает и при восстановлении входа. После выбора только организации
синхронизация ждёт явного выбора магазина. Переходы между страницами не запускают
её повторно. При смене контекста предыдущая синхронизация отменяется;
новая начинается после проверки доступа к выбранному магазину.
Прогресс виден на главной странице и в каталоге. Отправка на весы остаётся
отдельным действием с подтверждением пользователя.

Кнопка «На главную» возвращает к карточкам, сохраняя поиск, выбор товаров и
черновик подключения. Во время отправки на главной доступны прогресс и остановка;
смена организации/магазина и редактирование подключения заблокированы.
«Настройки подтверждены» означает проверку параметров оператором, а не текущую
доступность весов по сети. Офлайн открывается то же рабочее место сохранённого магазина.

Production renderer загружается с origin `maria://app`, как в POS. Для входа
сервер должен разрешать этот origin и dev-origin `http://localhost:5175`
в `CORS_ORIGINS` с credentials. Production API использует HTTPS
и совместимые cross-origin refresh-cookie (`SameSite=None; Secure`).
Настройки cookie локального backend-окружения отличаются, поэтому восстановление
входа отдельно проверяется с production-сборкой и целевым API.

При открытии раздела Maria приложение проверяет refresh-cookie. После успешной
проверки учётной записи, магазина и доступа к каталогу сохраняется локальное
разрешение на восемь часов, защищённое Electron safeStorage. Оно позволяет
открыть последний каталог и вручную отправить товары после отключения интернета,
в том числе после перезапуска. Возраст цен показан отдельно от срока доступа.
При недоступном safeStorage вход работает онлайн, но разрешение на перезапуск
офлайн не сохраняется. Выход и подтверждённый отзыв доступа отменяют разрешение.

## Каталог Maria → локальная БД → весы

1. В web-клиенте Maria откройте **Настройки → Организация → Весовые штрихкоды**,
   назначьте префикс и включите профиль. `20` — предложение web-формы; приложение
   весов всегда использует фактически сохранённый префикс из API.
2. В разделе Maria приложения весов выберите организацию и магазин. Загрузка
   запускается автоматически: `sync-start?unit=kg`, страницы, затем изменения
   от исходного курсора. Неполная загрузка не подменяет последнюю полную копию.
   Последующие обновления — вручную и раз в минуту; «Остановить» приостанавливает
   автоматическое обновление до ручного запуска или нового подключения сессии.
3. Откройте «Настройка весов». Настройте IP, UDP-порт и локальный адаптер. Подтвердите настройки прибора:
   два знака цены, kg, кодировку ASCII или Windows-1251 и тип штрихкода **07**
   (отдел = префикс организации, затем PLU5 и вес в граммах5). Сначала проверьте
   этот формат и кодировку на одном товаре; массовый режим не заменяет аппаратную проверку.
4. Откройте «Каталог товаров», затем предпросмотр всех готовых или выбранных товаров. Приложение проверяет
   `scale_plu`, активность, магазинную цену и имя `scale_name` либо `name` до 36 байт.
   Названия не обрезаются и не транслитерируются автоматически. Исправляйте
   неподдерживаемые имена, отсутствующие PLU и цены в Maria.
5. Нажмите «Загрузить». Отправляется один товар на пакет с ожиданием ответа.
   Изменения после предпросмотра требуют нового предпросмотра. Точный набор и
   пакеты сохраняются перед отправкой. Нет автоматических повторов после таймаута.
6. Проверьте товар и печать на весах. ACK подтверждает пакет, но не чтение
   содержимого памяти обратно. Результат и байты обмена можно экспортировать.

Оформление этикетки загружается через официальный RLS/RTLabel отдельно. Приложение
передаёт товары и цены, не заменяя растровый макет. Удалённые/неактивные товары
исчезают из актуального каталога; ранее отправленные отмечаются для ручного
удаления с прибора. Удаление отдельных PLU и удалённая печать не реализованы.

В «Настройке весов» доступна кнопка **«Удалить все товары с весов»**. Подтвердите
IP и порт сохранённого устройства: удаляются все его товары, включая загруженные
другими программами и магазинами. Каталог Maria, локальная БД и макеты этикеток
не очищаются. Команды предназначены только для профиля `LB1.00 / LS` с именем
PLU 36 байт; другой профиль блокирует удаление.

Очистка выполняется только после отдельного подтверждения, без автоматических
повторов. Во время неё загрузка товаров заблокирована. Остановка
не отменяет уже отправленные команды. При потере ответа результат отмечается
как неизвестный: проверьте товары на весах перед повтором. После подтверждённой
очистки весь каталог можно загрузить заново; прежняя история остаётся в отчётах.
Кнопка «Сохранить отчёт об очистке» экспортирует JSON и TXT с этапами и байтами
обмена. Прерванная очистка после перезапуска автоматически не продолжается.

Команды очистки проверены по официальной программе RLS1000 v1.129 и в UDP-тестах;
аппаратная проверка очистки на RLS1100 ещё требуется. Ответ ACK подтверждает
команду, поэтому после первого запуска проверьте, что прежние PLU не вызываются.

SQLite и история находятся в `userData/catalog/`. В SQLite нет bearer-токенов,
паролей и refresh-cookie. Кэш разделён по API, пользователю, членству, организации
и магазину; переключение контекста останавливает фоновые операции.

## Проверки и сборка

```sh
npm test
npm run lint
npm run typecheck
npm run format:check
npm run build
npm run smoke:catalog
npm start
```

`npm run build` создаёт `out/`. `npm start` открывает собранное приложение.
`npm run smoke:catalog` проверяет собранный worker, SQLite и офлайн-доступ
во встроенном Node.js Electron с отдельной временной базой.
`npm run build:win` на Windows создаёт NSIS-установщик x64 в `dist/`.
Workflow Build выполняет проверки и сборку установщика на Windows, сохраняет
установщик в артефактах запуска на 14 дней.
Отдельный workflow Lint проверяет ESLint и форматирование на Ubuntu.
Оба запускаются для PR в `main` или вручную. Dependabot ежемесячно проверяет
обновления npm-зависимостей. Конфигурации и шаблон PR взяты из `pos-system-client`.

## Релизы Windows

Workflow Release Windows собирает и загружает установщик при публикации
GitHub Release. В **Settings → Secrets and variables → Actions → Variables**
задайте `SCALES_API_URL` — корневой HTTPS URL production API без `/v1`.

Создайте релиз из `main` с тегом `vMAJOR.MINOR.PATCH`, например `v0.1.0`, и
опубликуйте его. Workflow возьмёт версию из тега, выполнит проверки и вызовет
`npm run release:win`. Версию в `package.json` перед релизом менять не нужно.
Для загрузки используется встроенный GitHub token с правом `contents: write`.

Постоянный адрес последнего установщика:

```text
https://github.com/maria-dev-team/scales-system-client/releases/latest/download/dukenai-scales-setup.exe
```

Для приватного репозитория скачивание требует авторизации GitHub.
Подпись установщика и автообновление внутри приложения пока не настроены.

Архитектура описана в [ARCHITECTURE.md](./ARCHITECTURE.md).
